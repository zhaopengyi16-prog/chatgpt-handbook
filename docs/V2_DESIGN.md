# V2 设计：从一本手册到多入口 AI 教程社区

**读者先选要完成的事，再按手边的工具和经验筛选。** 同一篇教程可以出现在几个入口，但只有一个地址、一份正文和一个发布动作。作者继续在 Sites 后台编辑；论坛继续区分游客、成员和站点所有者。GitHub 管代码和设计，D1 保存内容与讨论，R2 存新截图。这份文档是第 1 批提案，不是已上线的功能。

| 已核对的 v14 入口 | 对升级的约束 |
| --- | --- |
| `app/page.tsx`、`app/chapters/[slug]/page.tsx`、`lib/data.ts` | 当前首页是章节目录。公开阅读取发布副本；管理员显式预览才读草稿。新入口必须沿用同一条可见性边界。 |
| `db/schema.ts`、`drizzle/`、`lib/content-revisions.ts` | 已有 settings 主键和章节草稿/发布列，无需迁移。旧修订有独立标记、版本及正文比对；V2 不重放它们，也不以历史稿为线上正文。 |
| `app/api/[...path]/route.ts`、`app/chatgpt-auth.ts`、`lib/guests.ts` | 复用现有来源、身份、归属、限流及审核边界。目录标签和论坛关联都不是授权凭证。 |
| `app/admin/`、`lib/blocks.ts`、`lib/content.ts`、`EDITOR_GUIDE.md` | 保留块编辑器与旧排版兼容模式。在读取层处理旧图片，不能用公开 HTML 覆盖后台原稿。 |

## 1. 分类：章节只有一份，入口可以有多个

正文仍以 D1 的 `chapters` 为准。分类页面引用同一个章节 ID，不复制正文；给章节加标签也不改变 URL、目录位置或小节锚点。现有 `db/schema.ts` 和两份 SQL 迁移已有 `settings(key PRIMARY KEY, value TEXT)`，本方案无需改表。

**一条版本化设置。** `taxonomy_v1` 的值为 JSON：`schema:1`、`revision`（每次成功写入递增）、`tasks/tools/levels` 三个数组、`emptyPolicy:"hide"|"comingSoon"`、`chapterTags` 和 `publishedChapterTags` 两张映射。数组每项是 `{id,name,icon,description,order}`。例如场景可写为 `{"id":"website","name":"做网站","icon":"window","description":"从一个小页面开始","order":5}`。ID 是固定路径段，重命名不改 ID；图标是内置原创图形的名称，不接受 HTML、SVG 源码或外链。

| 维度 | 初始选项（显示名 / 稳定 ID；由左到右为顺序） |
| --- | --- |
| 想做什么（多选） | AI 建模（Blender 等三维建模工具） / `ai-modeling`；写代码 / `coding`；做工程 / `engineering`；改文件 / `files`；做网站 / `website`；做视频 / `video`；生图片 / `images` |
| 工具（多选） | ChatGPT 与 Codex / `chatgpt-codex`；Claude / `claude`；国内 AI / `domestic-ai`（DeepSeek、Kimi、通义等）；多模型与开源工具 / `multi-open`（含 OpenCodex 号池）；智能体 / `agents`；WorkBuddy / `workbuddy`（腾讯桌面智能体） |
| 难度（单选） | 基础教程 / `basic`；高级技巧 / `advanced`。界面从配置生成，不能写死为永远只有两个选项。 |

`chapterTags[chapterId] = {tasks:[],tools:[],level:null}` 是已保存草稿的标签；`publishedChapterTags` 同形，是上次明确发布的快照。例如「用 Claude 做网站（基础）」的标签为 `{tasks:["website"],tools:["claude"],level:"basic"}`。两张映射不得引用同一可变对象。草稿可缺标签；没有标签的历史公开章节仍可在完整目录找到。分类名称、顺序与空分类设置属于全站导航，管理员保存即生效；变更某一章的归类则随那一章发布。

**读与缓存。** 公共查询只读取设置的公开投影，并以 `lib/data.ts:publicChapters()` 的条件（`published_body IS NOT NULL AND deleted_at IS NULL`）与发布标签取交集；不向浏览器返回整个设置值。计数按不同章节 ID 去重，不因草稿、回收站、待审讨论或草稿标签变化而增加。按无筛选时的公开数决定空分类策略：首发默认隐藏，作者日后可在后台全站切换为展示「即将上线」，不列草稿标题。筛选组合为零只显示「没有符合条件的教程」和清除筛选。服务端一次请求解析、校验一次并重用；首版不跨请求缓存，管理/预览响应不共享缓存。设置缺失、版本未知或损坏时公共页退回现有章节目录，后台显示明确原因；不以默认值覆盖坏数据。

**写入校验。** 三组使用字段白名单；建议每组 ≤64 项，ID 匹配 `^[a-z][a-z0-9-]{0,47}$`，拒绝保留键，组内 ID 与去首尾空白后的名称不重复；名称 1–40 字符、说明 ≤200 字符，按纯文本展示，图标须在白名单内。顺序为非负整数，排序提交必须恰好包含该组全部 ID 一次，服务端重排为连续序号。映射键必须是库内真实章节 ID；数组去重、只接受对应组有效 ID、难度为一个合法值或 null。控制整份文档 UTF-8 大小（初始预算 128 KiB，超限拒绝写入并提示），不限制章节正文本身为这个大小。若收录量接近上限，先提分键设计，不删数据腾空间。

**并发约定。** 管理操作带读取时的 `expectedRevision`，服务端读旧值、校验、构建新值，用 `UPDATE settings … WHERE key=? AND value=?` 比较原始值后替换；竞争返回 409，界面保留本地编辑、允许重读对照。客户端不能提交包含两张映射的整份设置来覆盖其他人的工作。已有引用的条目不得直接删除：检查草稿、发布快照、软删除章节及第 4 批引入的论坛关联；返回 409 和仅管理员可见的引用定位。先改归类并发布或移除引用，再删空分类；需保留旧分类链接时优先改显示名，不复用已对外分配的 ID（可在设置保留已退役 ID 集）。论坛写入与分类删除都要在相应 D1 batch 内再次校验：在分类删除的条件 UPDATE 中查论坛引用；在论坛写入的条件 SQL 中匹配已校验的 taxonomy 原值。不能只依赖进入事务前的两次查询。

## 2. 读者从哪里进入

| 入口 | 内容和边界 |
| --- | --- |
| `/` | 首屏问「你想做什么？」；按顺序预留七个场景入口，是否出现依空分类策略。桌面侧边、手机下方提供工具与难度筛选。下方保留「全部章节」入口、最近已公开讨论及更新摘要。最近讨论复用论坛对 approved、非隐藏内容的查询，按时间排序；更新页当前是静态页面，摘要复用同一份公开更新条目，不用草稿保存时间生成动态。 |
| `/learn/[task]` | 场景名称、介绍及已发布教程；例：`/learn/website?tool=claude&level=basic`。筛选可清除、链接可收藏，刷新与后退保留条件。 |
| `/tools/[tool]` | 使用某个工具能做什么；可按场景、难度筛选。场景和工具允许多值时，同一组取并集，不同维度取交集，难度单选。先求发布列表再排序，沿用 `published_position,id`。 |
| `/chapters/<slug>.html` | 继续在现有页面呈现唯一正文；面包屑「首页 › 排序最前的已发布场景 › 章节」，无场景时经「全部章节」。列出全部公开场景/工具标签和难度；保留原有标题锚点、上一章/下一章与讨论入口。管理员 `?preview=1` 才取草稿，其他人只能看到发布态或 404。 |
| `/community`、`/topics/<id>`、`/updates`、`/contribute` | 保持原址及旧的 `?chapter=…` 筛选；保留现有 `/chapters/boundaries.html` 到 `/chapters/appendix.html#before-sharing` 的条件跳转，不把旧章统一重定向到首页。 |

未知路径 ID 返回 404；被设置为隐藏的空分类不提供列表入口，直接访问同样返回 404，不透露草稿。展示模式下直接访问空分类只见公开简介及「即将上线」。已知分类页遇到无效查询参数，给出移除该筛选的链接；不擅自返回看似命中的全量结果。第 2 批先沿用当前样式和语义导航。

## 3. 作者怎样维护分类、保存和发布

在 `app/admin/panel.tsx` 工作台增加「分类」页签，按场景、工具、难度分别新增、编辑、移动和删除。提供上下移按钮，拖拽仅作为补充。可预见哪些章节引用该项；删除前展示影响。章节编辑面板在标题、简介旁增加场景/工具多选、难度单选。沿用当前“有未保存修改”的提醒、保存草稿、预览已保存草稿和发布按钮；标签不进入 `lib/blocks.ts` 的 HTML，也不占用图库或编辑器的撤销栈。

| API（建议契约） | 访问与结果 |
| --- | --- |
| `GET /api/admin/taxonomy` | 仅管理员。返回当前版本、配置、两张标签映射和引用摘要；未初始化返回清晰的状态，不隐式写入。 |
| `POST /api/admin/taxonomy` | 仅管理员，动作 `initialize`（见第 4 节）或 `create`（组别、单项、期望版本）；已初始化重复调用不改数据。 |
| `PUT /api/admin/taxonomy` | 仅管理员，动作 `edit`、`reorder` 或 `setEmptyPolicy`；分别接收组/ID 与可编辑字段、完整顺序、策略枚举，附期望版本。拒收映射、正文、发布状态等多余字段。 |
| `DELETE /api/admin/taxonomy?group=…&id=…&revision=…` | 仅管理员，无请求体。移除未引用条目；不级联改写正文、历史帖子或发布映射。 |
| 现有 `PUT /api/admin/chapters/:id` | 保持 `action`、`version` 与原响应契约；新客户端在保存/发布时可带 `tags` 和分类期望版本。后台读取章节时补充标签及版本；旧客户端缺省标签时按当前已保存草稿标签处理，不得清空。 |

严格匹配路径和方法；均在现有来源、登录、管理员及游客检查完成后分派。跨站写入 403，游客 401，非管理员成员 403；非法字段/类型/引用 400，资源不存在 404，旧版本/删除仍被引用/重复 ID 409，超限 413。所有服务端写入使用绑定参数。导出沿用现有接口与字段，显式增加已知分类键及后续论坛关联的备份，不把整张 settings（含身份与其他内部键）暴露出去。

**同步正文和归类。** 保存只变草稿映射，发布才把该章草稿标签拷到发布映射；撤回/软删除后无公开结果，恢复仍是草稿，须再次发布。章节 `version` 原有乐观锁、正文净化以及权限判断都保留。涉及两处写入时在同一个 D1 `batch` 中同时验证章节版本和设置版本：先以旧设置原值和现有章节操作的同一前置条件抢占更新（写入新 revision 及该次唯一 token）；原章更新再附带“设置值确为本次 token”的条件。失败时两个条件均不生效；SQL 异常整批回滚。不要把“影响 0 行”当作抛异常，也不要在两次独立请求中先存正文再补标签。无标签的旧调用同样保证发布快照与正文一致。验收：两个窗口同时保存、分类被重命名/删除或版本过期时均不能出现半发布；409 后保留编辑文本。

## 4. 初始内容：七个入口，七份未发布的草稿

**已有内容只建映射。** v14 集成测试中的七个公开 ID 与 `db/seed.json` 的早期八章不完全相同。按 ID 匹配现场存在的章节，不依赖标题、当前位置或原始 seed 序号。首次初始化可把以下映射赋给草稿，只有当时确实已发布且未删除的行才同时赋给发布映射；缺失的旧章不补建。其他自建章节保持原状。

| 现有章节 ID | 场景 | 工具 | 难度 |
| --- | --- | --- | --- |
| 第 1–3 章：`getting-started`、`chatgpt`、`codex` | 暂不指定 | ChatGPT 与 Codex | 基础教程 |
| 第 4 章：`desktop` | 写代码、做工程 | ChatGPT 与 Codex | 基础教程 |
| 第 5 章：`practice` | 暂不指定 | ChatGPT 与 Codex | **高级技巧**（第五章是例外，不同时打基础标签） |
| 第 6 章：`models` | 暂不指定 | 多模型与开源工具 | 高级技巧；保留 OpenCodex 号池内容，风险提示留给内容批次 |
| 第 7 章：`appendix` | 暂不指定 | ChatGPT 与 Codex | 基础教程 |

**新草稿**使用固定 ID `v2-starter-<场景ID>`，工具留空，难度 `basic`。正文仅放三个带稳定锚点的原生 heading 块（经 `renderBlocks` 和 `cleanHtml`），不配图、不填示例正文；作者逐节补充后决定何时发布。

| 场景 | 草稿标题 | 小节占位 |
| --- | --- | --- |
| AI 建模 | 用 AI 辅助在 Blender 做第一个三维模型 | 准备参考图与尺寸；从基础几何体搭出外形；检查比例并导出模型 |
| 写代码 | 让 AI 帮你改一小段代码 | 准备最小示例；说明预期改动；验证行为 |
| 做工程 | 从任务说明到工程检查 | 拆分任务；整理工作目录；记录验证结果 |
| 改文件 | 安全地批量修改文件 | 留好副本；预览变更；抽查并撤回 |
| 做网站 | 做出你的第一个网页 | 画出页面结构；搭建页面；检查手机效果 |
| 做视频 | 从脚本到一个短片 | 定义片段；准备分镜；检查成片 |
| 生图片 | 生成一张符合用途的图片 | 确定尺寸与用途；写提示并比较版本；导出检查 |

**一次性初始化。** 由管理员在后台显式执行。先确认 v14 基线就绪、读已有章节状态；复用 `settings` 主键作哨兵，绝不删除或重置 `taxonomy_v1`。在一个 D1 batch 中：

1. 仅当 `taxonomy_v1` 不存在、七个保留 ID 均未占用（含回收站）、读到的原章状态仍匹配时，用条件 INSERT 抢占该键，保存初始分类/映射和本次随机 token。
2. 七条章节 INSERT 均校验键持有**本次** token；只插入不存在的 ID，位置接在现场最大位置之后。全部 `published_*` 为 NULL，无发布映射，`deleted_at` 为 NULL。绝不 UPDATE、REPLACE 或重新套用历史正文修订到原章节。
3. 发生 SQL 错误时整批回滚；并发失败者重新读取：键已存在则返回“已初始化”，无键但有 ID 冲突则返回 409 并列出冲突供作者处理；其他前置条件变化提示重试。即使后来作者删除草稿，再次打开后台/重复初始化也不会重新生成。管理员若回退到旧程序，留在库中的未发布草稿仍不公开。

验收同时比较初始化前后已有章节的**所有字段**，包括正文、发布副本、版本与时间戳；对重复执行、竞争、保留 ID 冲突、事务中途失败、已编辑或删除草稿分别做回归。新草稿仅在管理列表和管理员预览可见；游客、普通成员均不能借筛选、计数、详情 URL、预览参数或 API 发现草稿。

## 4b. 下线旧截图，但保留作者的原文

**同一份正文，两种视图。** 章节公开页与管理员的「读者效果」预览均隐藏旧图；块编辑器保留对应位置，让作者替换。服务端不能只加 CSS：旧图片的地址不能进入读者页面，否则浏览器仍会请求它。整个过程不向 D1、R2 或历史备份写入数据。

| 出口 | 实现与边界 |
| --- | --- |
| 章节页、公开效果预览 | 在 `app/chapters/[slug]/page.tsx` 选定正确的 `published_body` / 管理员草稿后，先用现有 `cleanHtml` 清理，再作**仅供显示**的投影。从投影结果生成目录、正文，再增加阅读链接。移除“保留原稿截图供对照”的固定提示。保留 `.html`、原有小节锚点及 `boundaries → appendix.html#before-sharing` 的现有回链。 |
| 编辑画布、旧版 HTML 块 | `lib/blocks.ts` 同时支持结构化截图和包含任意嵌套内容的 `legacy` 块。在 `app/admin/block-editor.tsx` 用原块 ID 将下线位置显示为「旧截图已下线，请替换或删除」，保留原图注供参考。兼容一个旧版块包含多张图与正文，只替换或删除选中的那张。编辑画布仍一块一个可选根，投影和标记不进入 `onChange`、撤销快照或可编辑正文；后台的读者预览与公开页共用规则。只读到旧块不算作者修改。 |
| 图库与插图 | 管理端对 `media.url` 使用相同判定；旧记录显示「已下线」，不生成缩略图请求，不给选择、插入或删除入口，不删除历史记录。所有插入入口（含旧版块、粘贴链接）均不可新增旧引用；服务端保存/发布验证只拒绝相对当前稿**新增**的旧图引用（按解析后地址及出现数比较），现存旧稿仍可保存。新图仍走现有后台上传与 `/api/media/<id>`；保留现有对草稿和已发布正文的引用检查、删除保护及 R2 接口。 |
| 共建页与历史下载 | 下线 `app/contribute/page.tsx` 的「离线阅读 / 下载原稿截图」区块，保留参与讨论与授权说明。公开路由不再挂载下载按钮或触发 `theme/downloads.js` 对 `handbook-html-core.zip`、`handbook-source-core.zip`、`handbook-images.zip` 的组合请求。历史源码和导出备份不等于线上下载入口。 |

**无新依赖的过滤。** 将读者投影提取为 Node、Workers 都可测试的纯函数。以已净化的 HTML 为输入，复用锁定版本的 `sanitize-html` 解析事件：在 `onOpenTag` / `onCloseTag` 维护本次调用独有的标签栈；命中旧 `img[src]` 标记其祖先 `figure`，命中完整 class token `hb-shot-placeholder` 则丢弃占位子树（在截图 figure 中则连空图框、说明一起去掉）；到结束标签用 `exclusiveFilter` 移除标记的整个子树。没有 figure 的独立旧 img 也去掉；仅包着旧图的放大链接不留死链。一个 figure 混放新、旧图时以“含旧图则整框移除”为准，在编辑器提醒作者拆分；在被移除子树外，旁边的正文、表格、代码示例和有效的新图保留。按 URL 路径完整前缀 `/assets/screenshots/` 匹配，允许 query/hash；同站绝对地址先归一，外站同名路径和 `/assets/screenshots-new/` 不误伤。避免正则截取 HTML、在 Worker 假设有浏览器 DOM、或在全局保存用的 `cleanHtml` 增加删除规则。

**验收与发布门槛。** 组合夹具覆盖嵌套链接/图注、独立 img、空截图框、多个旧图、正常 R2、新旧图相邻、转义在代码里的 HTML；比对公开服务端 HTML 与浏览器请求均无旧图/旧包。真实路由上旧章返回 200，未发布章不对游客开放。编辑器可定位替换/删除、撤销；只打开或预览前后比对 D1 的草稿、已发布正文、版本及媒体记录不变。第 2 批将 `tests/integration.ts` 中对旧资源物理存在的断言（例如 `existsSync('public'+shot.src)`）替换为上述行为断言，保留既有权限和数据保护测试；本设计批不改测试。上述门槛通过前不能从开源导入版本发布 Sites。

## 5. 论坛：讨论按场景找到，权限仍由帖子决定

读者在 `/community` 先选场景分区，或进入「全部讨论」「未关联场景」。维持既有的搜索、四种用途分类（使用求助、经验分享、内容纠错、功能建议）和章节筛选；它们与新加的工具、场景筛选取交集。分享筛选结果使用 `?task=…&tool=…&category=…&chapter=…`；更换条件回到第一页，继续使用置顶优先和现有分页。发帖可**只选场景或工具，不必编造一个关联章节**。旧帖无标签，仍可搜索、访问、回复和在原章节下找到。

| 数据或入口 | 约定 |
| --- | --- |
| 每帖标签 | 为设置表新建按帖分开的键 `topic_tags_v1:<topicId>`，值形如 `{"task":"website","tools":["claude"],"sectionId":null}`（示例 ID 以分类表实际值为准）。一个可选主场景，使分区不重复；工具可不选，去重后最多 3 个；小节锚点可空。回复继承话题上下文，无须另存标签。没有该键与无标签等价，不批量改旧帖。不得向普通用户开放通用 settings 写接口。 |
| 发帖与校验 | 扩展现有 `POST /api/topics` 的可选字段；旧客户端照常发。现有 `chapterId` **已可空，不修改其校验**：有值须先经 `identifier()`，且在 chapters 中已发布、未删除。场景/工具在相应 taxonomy 组中校验，未知、错组、超限或错误类型返回 400；不拿标签伪装成 `chapterId`，也不把旧的 `category` 四值换成场景。提供 `sectionId` 须同时提供有效章节，且是已发布正文中的 h2 锚点。日后小节移除时讨论仍可读，链接退到章节。 |
| 写入与授权 | 使用原 `route.ts` 授权链、签名游客 Cookie、限速、作者归属和服务端审核状态；不另开游客写标签端点。新增话题与其标签放同一 D1 batch；带标签时在条件 INSERT 中重验分类版本，标签只随本次成功的新帖插入，分类发生竞争则返回 409、不留孤儿。相同作者/请求 ID 重试返回原结果，不覆盖原标签；异主冲突仍 409。编辑标签走现有 topic PUT，只有原本有权限且未受锁帖限制的人能改；版本冲突 409 时标签也不得写入。做法示例：同批次先按“允许更新且版本匹配”的原行条件 `INSERT … SELECT … ON CONFLICT` 元数据，再用同一条件更新帖子并检查影响行数；缺省标签字段不改旧值。有变动的写操作在同一批次同时确认分类引用仍有效，条件不匹配时两处均不写。纯审核/置顶/隐藏不改标签；删除或审核拒绝话题同步清理对应元数据，须以本次删除成功为条件，拒绝陈旧版本不删关联。 |
| 读取、计数、导出 | 从有权读取的 topics 出发，通过主键 `settings.key = 'topic_tags_v1:' || t.id` 左联，再按绑定参数检查 JSON 字段（多工具用 `EXISTS … json_each`，畸形/缺失值按空处理）。列表、分区计数和总数共用同一组可见性、搜索及标签条件，在数据库分页前完成，而非在每页 20 条结果上二次过滤。公开列表仍只含 approved、未隐藏帖子；详情、回复和管理员队列沿用各自原权限。不将整份 settings 或待审标题传到客户端。管理员导出增加明确白名单：taxonomy 与话题标签，并保留 `content_backup:*` 等原导出；绝不批量导出游客签名密钥。 |

**从章节发问。** 第 4b 节处理完正文后，在每个 h2 对应的小节末尾（下一 h2 之前；最后一节在正文末尾）加入「就本节提问」。链接到 `/community?chapter=<id>&section=<anchor>`，由论坛预选并展示可撤回的章节上下文。没有锚点的历史 h2 可按标题和同名序号生成在该版本稳定的只读锚点、去重并在服务端用同一投影验证。URL 参数逐项编码；不把用户提供的标题当 HTML，不将链接、锚点写回 D1。公开话题页地址仍为 `/topics/<id>`。

**帖子呈现。** 帖子和回复继续存源文本，编辑时读原文；仅展示时解析围栏代码块、行内代码、列表、链接与普通段落。先识别代码段，再转义所有用户文本，禁原始 HTML/图片；生成的标记再用现有 `sanitize-html` 专用白名单清理（`p br ul ol li pre code a`，链接仅明确允许的 http(s) 地址并加 rel；无样式/事件属性、嵌入或协议相对 URL）。非法链接、图片和不支持的语法显示为普通文字；保持原有提交长度上限。管理员审核预览使用同一渲染器。既有帖子不需要转存。

**游客与管理员。** 游客提交收到服务器的 `pending:true` 才向本设备 `localStorage` 写一条回执（话题/回复 ID、时间、标题或文字摘录），按 ID 去重，限条数和保留期，可一键清除；读、解析、写和删除全部放在 `try/catch` 中，存储不可用不影响提交。社区页「我提交的内容（待审核）」说明这是本机回执，未公开不代表能跨设备查询；公开后若能从已公开数据匹配则更新，未查到不声称已被拒。没有凭回执获取待审原文、编辑或跳过审核的 API。后台导航复用 `GET /api/admin/review` 已有的 `total`（待审帖子 + 回复），审核/拒绝后刷新，失败不显示假零。第 4 批暂缓「一键生成置顶示范帖」，管理员继续用现有发帖和置顶入口。

**验收。** 以 `tests/integration.ts` 现有同源、伪造 Cookie、游客 401、成员越权 403、限速、待审不可见、锁帖/隐藏、版本冲突测试为基线。额外覆盖：拒绝提交两个主场景或四个不同工具（400），允许一场景三工具和全部留空；仅选场景、仅选工具、不选章节、真实章节与小节、草稿/已删除章节/伪造锚点、错误维度；交集筛选分页与计数；访客看不到 pending/隐藏话题的内容或分区数；同一请求重试、编辑冲突、拒绝旧版本时标签不变；游客不能改标签/回复，成员不能改他人内容，非管理员访问管理接口仍为 401/403；Markdown 的 `<script>`、混合大小写的 `javascript:`、`onerror`、图片与代码中的尖括号；不可用或损坏的 localStorage。回退到此前**已通过第 2 批公开渲染门槛**的版本时，旧代码忽略话题标签、帖子原文仍可读，无须删除记录。

## 6. 原创像素沙盒：先验证阅读，再换全站

## 7. 按什么顺序上线，怎样退回

每批从已审核的基线建分支，提交可独立审核的 PR；作者将 PR 和验证报告交 Claude 审查，再决定是否合并。代码变更至少运行 `node tests/run.mjs` 和 `pnpm build`；失败要报首个失败位置和未执行部分。作者负责 Sites 预览和正式发布。本批和预览样式阶段都不能把预览当作全站发布许可。
