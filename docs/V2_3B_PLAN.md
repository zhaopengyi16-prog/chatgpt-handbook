## 3. 分类、材质与学习路线

### 全部从公开投影生成

首页使用一次 `readPublicCatalog()` 结果生成场景卡、工具卡、难度路线和教程目录；讨论用 `recentPublicTopics()`，更新用 `publicUpdates`。计数只来自已发布章节与 `publishedChapterTags`，不从草稿映射或后台列表拼接。重复归类不重复计同一篇教程。

所有可公开分类按配置顺序循环，不写死七个场景、六个工具或两级难度。学习路线为「第一项公开难度 → 选一个场景 → 其余公开难度」；零项时仅显示场景入口，一项或三项以上也正常。LV 是展示步骤号。`AI 建模` 仍指 Blender 等三维建模。

**保留线上 `emptyPolicy` 原值。** 当前为 hide 时，空场景仍隐藏；作者以后在现有后台显式选择 comingSoon，零篇分类才显示「即将上线」。发布样式、打开页面或保存材质都不能顺带改变这个设置。hide 下新增分类在拥有公开教程后自动出现；comingSoon 下新增分类立即出现公开名称与说明。此规则同样适用于工具与难度，不为凑齐路线偷读后台分类。

### 可选 material 字段

- material 是可选字段。只扩展 `settings.taxonomy_v1` 中分类项的 JSON，不修改数据库结构；键仍为 taxonomy_v1，`schema` 版本号仍为 **1**，不升版、不改顶层 JSON 格式。白名单：`grass / dirt / stone / water / sand / wood / ember / gem / snow`。
- 旧 JSON 没有该字段仍合法。读取时以 `order % 9` 计算默认材质，且在隐藏空分类之前计算；不写回数据库。显式材质不随排序改变；自动材质随排序轮换。
- 后续推广 PR 才在管理员分类表单新增「自动 + 九种材质」，且必须等兼容 PR 先上线并验证。这是本计划唯一新增的分类设置控件，不能借此改动既有章节编辑、草稿、发布或权限逻辑。创建时自动值省略字段；编辑时省略代表保留，`material:null` 代表恢复自动，规范化后删除字段，null 不写入存量 JSON。
- 严格拒绝任意颜色、URL、CSS、HTML、对象及未知字段；继续保留名称/ID/数量/大小和引用校验，不能为了兼容材质而放开全部未知键。
- **不改现有 CAS/writeToken 机制**：expectedRevision 校验、原始 JSON 比较更新、revision + 1、唯一 writeToken 及同一 D1 batch 的章节/标签原子性均保持原算法和 SQL。并发保存与章节发布竞争时返回 409，保留用户未提交输入，不能绕过锁，也不能出现正文与分类只成功一半。
- 材质、分类名称、排序、空策略属于全站导航设置，管理员保存后生效；章节标签仍随章节发布快照生效。后台应说明两者区别。
- 数据导出必须保留字段。现有工程没有通用在线恢复 API：本批只在隔离数据库验证导出 JSON 往返，不宣称增加了完整恢复功能。

### 必须先处理的回退兼容

**v16 不兼容带 material 的数据。** 已只读核对 Sites v16 来源为 `33e08f68e4a179e9f25f85e25152141043cf65f1`；其 taxonomy、分类/章节写入、公开投影及相关路由文件与本轮 main 基线一致。该版本 `category()` 的严格白名单没有 material，故即使 material 值合法也会将整个分类文档判为 invalid。结果：

- 管理员分类接口返回 invalid，分类编辑/初始化返回 409，不覆盖原数据。
- 公开首页回退原章节目录，正常分类投影与筛选不可用；不能保证场景/工具链接继续呈现原分类页。
- 章节保存/发布经 saveChapterWithTags 遇到 invalid 返回 409；既有章节正文、版本和媒体不会因此自动清除。

这是对保存版本源码的只读核对，未向线上 D1 注入错误数据，也未执行回退。PR #6 基线具有相同风险。**一旦启用 material，v16 与 v14 都不可作为回退目标；绝不回到 v14。**

3b 按以下顺序分两份可审查 PR：

1. **兼容准备**（本轮唯一功能 PR，`feat/v2-material-compat`）：基于 main 加方案文档提交，保留全部旧外观；只扩展存量 material 的读取、校验和保留。旧 JSON 仍合法且不补字段；覆盖九值、非法值、读取不写、字段保留、导出和原子性测试。**不开放材质 UI，API 的 create/edit 显式提交 material（含合法值/null）也必须 400**，防止共享解析器意外提前开放写入。现有改名/排序/保存章节要保留合法的已有 material。不得初始化或改写线上设置。完成后开 PR 并停止。
2. **全站推广**：在兼容基线上接入共享视觉、动态首页、后台材质选择与 B1–B5。推荐分支 `feat/v2-style-rollout`，按下节顺序拆提交。

**发布顺序是硬约束：兼容 PR 审核 → 作者另行授权合并 → Sites 预览 → 兼容版本正式上线并验证 → 记录该版本号/提交和可用构建 → 后续 PR 才开放后台/API 写 material。** 上线验证包括现有1–7章/分类可读、旧编辑保存/预览/发布正常、旧数据无自动变更，且主动新增 material 的请求仍拒绝。没有该验证记录就不开始第二份推广 PR。以后最低回退目标为这份已上线验证的兼容版本，绝不退到 v14，也不退到不识别 material 的 v16。不得删除 taxonomy_v1、重置分类或批量删字段解决回退。每个 PR 完成后停止，合并与发布都需要后续明确授权。

## 6. 300 KB、手机 LCP 与字体首屏

**硬验收对象：生产构建的游客首页，在 375×812、浏览器冷缓存条件下，整页实际传输 ≤300,000 bytes。** 这是首页全资源预算，不是只算字体。管理员页、成员态和长章节另测并报告，不把它们默默算进同一个首页门槛，也不把首页达标等同于全站均达标。

- 使用新建、允许的隔离浏览器会话或等效明确禁用缓存的测试环境；无缓存/Service Worker 命中，普通 hard reload 不自动等于冷载。连续做三次独立冷载，每次均须达标并报告最大值。
- 使用候选版本真实公开数据，记录分类 revision、公开教程/分类数、测试时间、浏览器版本和 DPR；不删内容或缩短标题凑预算。未来新增内容后应重新计量，不承诺任意数据规模始终小于300KB。
- 统计主文档以及全部自动加载的 JS、CSS、WOFF2、图片/内联资源所属文档、favicon、RSC、API 和响应开销。记录字体就绪、页面网络稳定及一次整页滚动后的请求总量；延迟加载仍计入，不靠延时请求或隐藏模块规避预算。内联资源不重复计数。
- 优先用真实网络/HAR或完整导航与资源时序记录；缺失条目必须说明并补齐，跨域时序返回0不等于零传输。按真实响应压缩结果计量，不能用本地 gzip 大小、磁盘文件大小或开发环境结果替代；重定向、自动预取与失败请求的实际传输也计入。
- 不为测试管理员预览伪造生产登录或改变权限；正式首页可用游客测量。若只能测本地生产构建，明确与 Sites 实际传输的差别，Sites 环境尚未测得时不得标为最终验收完成。
- **同批报告手机 LCP**：三次375×812冷载分别记录 LCP毫秒值、LCP元素、测试网络/CPU条件与 before/after，同表展示传输量；LCP在滚动/点击前采集，整页滚动的追加流量另记并计入上述总预算。不拿桌面LCP、平均值或静态估算代替手机实测；环境无法采集则明确未验证，不省略该项。用户未指定LCP数值阈值，本方案不自行声称一个已批准阈值。
- **字体不得阻塞首屏渲染**：保持 unicode-range 分片和 `font-display:swap`，首屏立即使用系统后备字形；不得用字体ready状态隐藏标题/导航、不得等全部分片加载再显示页面或初始化交互，不整包preload。慢速/阻断WOFF2时验首屏文本仍可见可操作，字体恢复后检查换字与布局偏移；记录瀑布/首屏截图和LCP元素，不能只检查CSS声明就算通过。
- 留总量、JS/CSS/字体/图像/API 分项、缓存/压缩状态、构建 SHA、浏览器/视口/测量方法。交付网络证据前去除 cookie、身份请求头、令牌等信息。

优先优化顺序：服务端渲染分类/路线和首页摘要；把导航/账号等客户端边界缩小；后台编辑器和通知组件不进入公开首页；去掉重复样式；木屋只在首页使用；复用现有字体分片，按真实标题字符选择热字集；最后依据实测热点调整。不会为追求数字删掉已确认模块、放松权限、整包预载字体或引入新依赖。

PR #6 的字体分片总计 1,130,160 B，并非首页下载量。预览曾只下载 2 个 WOFF2，但真实章节/帖子/分类名称可能触发更多分片，必须重测。原字体声明 CSS 同样计入预算。缺失的 116 个 GB2312 汉字逐字回退到系统字体；核验全站固定文案，并用生僻字、长名称和未来作者输入验证回退不会丢字或破坏布局。不能承诺所有未来输入都呈现像素字形。
