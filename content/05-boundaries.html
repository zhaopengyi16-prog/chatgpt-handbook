5.1 先确认资料归属与使用范围

处理一份材料前，分别确认：你是否有权使用它、是否允许发送给当前服务、是否允许把它的内容放进输出或公开教程。允许用 AI 辅助处理，不等于允许将原资料对外公开。

资料类型处理方式需要核对
公开文档与公开项目按来源和许可引用，保留出处。公开可读不等于可以任意再分发。
个人原创资料按需要提供相关部分。其中是否混入他人信息或第三方素材。
客户材料按适用授权匿名化、删减或使用示例数据。名称、联系人、订单、报价等能否关联回真实客户。
组织内部工程材料依照组织已确认的范围，在获准的服务和工作空间中使用。接收方、任务范围与输出的传播范围。
密码、密钥和私钥通过专门的认证方式或受控输入处理。避免进入普通聊天、公开代码、截图或共享日志。

不能只凭“源代码”“BOM”或“硬件原理图”这些文件类型决定是否能使用。应依据资料归属与实际授权判断，并把任务无关的材料移出可访问范围。

5.2 如何做一份可用的脱敏示例

  1. 将客户、组织、人员和项目名称换成一致的示例名称。
  2. 清理邮箱、电话号码、地址、订单号和内部链接。
  3. 把商业金额、非公开参数和内部时间线替换为明确标注的演示数据。
  4. 保留教学必需的字段、结构、输入输出关系和操作步骤。
  5. 检查截图侧栏、文件名、窗口标题、日志与图表标注，避免正文处理后图片仍泄露信息。
可复制提示词
请把这份材料整理为可公开教学的示例。
保留：任务流程、字段结构、操作方法和验收方式。
替换：人员、客户、组织、项目、账号、地址及非公开参数。
示例数据必须注明为演示数据，不得冒充实际结果。
列出需要人工确认的内容，但不要在审阅报告中再次完整复写敏感值。

5.3 了解资料实际发送给谁

使用插件、第三方模型或本地网关时，要分别确认每个接收方。客户端在本机运行，只说明客户端的位置；如果它调用外部模型，相关请求仍可能发送给模型供应商。

使用方式需要确认的环节
ChatGPT 工作空间当前账号、工作空间及适用的数据处理设置。
通过插件连接外部服务插件提供的工具、外部服务、账号和读写权限。
本地网关连接其他模型本地日志与配置、实际供应商、上游地址和附属工具服务。

OpenAI 当前说明 Business 业务数据默认不用于训练；这不应自动外推到另一个供应商、第三方中转或所有插件服务。订阅登录和 API Key 登录适用的管理与数据设置也需要分别核对。

参考：Business 与数据说明 · 登录方式与适用设置

5.4 用规则说明意图，用权限限制操作

提示词和 AGENTS.md 用于说明任务约定。实际文件读写、网络访问和外部服务动作，还需要由当前环境的权限机制约束。.gitignore 管理的是 Git 忽略规则，也不能用来阻止工具读取文件。

  • 只开放任务需要的目录、账号和工具。
  • 修改前保护已有工作，明确本次范围。
  • 删除、覆盖、推送、发布及影响外部数据的动作，核对具体目标与授权。
  • 首次使用插件或脚本时，先在示例项目中检查实际行为。

参考：权限配置 · Git 忽略规则

5.5 检查真实结果与未验证项

交付物检查重点
报告与资料总结数据、出处、遗漏和结论是否对应原始材料。
代码修改实际 diff、构建与测试结果、已有工作是否保留。
硬件或嵌入式方案电气条件、时序、保护和需要实机验证的部分。
公开网站与教程正文、图片、下载包和源代码中是否残留内部信息。

区分“已经执行”“建议执行”和“无法验证”。模型的自查和总结可以帮助定位问题，但不能代替实际文件、日志、测试或人工确认。

5.6 在公开讨论中提问

发布问题时提供最小可复现示例：入口、版本、操作步骤、错误表现与预期结果。删除账号凭据、客户资料和无关项目内容；不要上传整份内部工程只为解释一个小问题。
