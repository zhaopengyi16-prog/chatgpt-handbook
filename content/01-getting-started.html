1.2 大模型与Agent的区别（必看）

在使用 GPT / Codex 前，需要先理解“大模型”和“Agent”两个概念。本手册不从技术原理角度展开，而是从实际使用方式进行区分。

大模型是什么

大模型可以理解为 AI 的基础能力，主要负责理解问题、生成内容、分析资料和进行对话。

GPT 是模型系列，ChatGPT 是使用模型与工具的产品。常见模型系列或相关产品还包括：

  • GPT / ChatGPT
  • Gemini
  • Claude

大模型更适合处理以下任务：

  • 回答问题；
  • 写文档、报告、周报；
  • 总结资料；
  • 翻译和润色；
  • 分析文字内容；
  • 生成方案初稿；
  • 帮助梳理思路。

简单理解： 模型提供理解和生成能力；对话产品还可能接入工具，完成文件处理和连续任务。

例如：

帮我整理一份会议纪要。 帮我把这段客户需求整理成内部任务清单。 帮我根据测试记录生成测试报告。 帮我分析这份 Datasheet 的关键参数。

这些任务通常适合直接使用 GPT 等大模型完成。

Agent 是什么

Agent 可以理解为基于大模型能力进一步封装出来的“任务型助手”。

它不只是回答问题，还可以围绕一个目标进行连续操作，例如读取文件、分析项目、修改代码、执行检查、生成结果等。

常见的 Agent 类工具包括：

  • Codex；
  • Claude Code；
  • 其他具备自动执行流程、调用工具、处理项目能力的 AI 助手。

Agent 更适合处理以下任务：

  • 阅读和分析代码项目；
  • 修改代码；
  • 排查 Bug；
  • 生成测试脚本；
  • 梳理工程目录；
  • 根据项目文件生成接口文档；
  • 按步骤完成一个连续任务；
  • 对某个工程或资料进行多轮处理。

简单理解： Agent 更像一个“能执行任务的 AI 助手”，不仅能回答，还能按照目标持续推进工作。

例如：

请分析这个代码仓库的主流程。 请帮我定位这个编译错误的原因。 请根据现有接口生成测试脚本。 请修改这个模块，并说明修改了哪些文件。

这些任务更适合使用 Codex 或类似 Agent 工具完成。

模型与 Agent 的区别

类型主要作用典型工具适合任务使用重点
大模型理解、生成、总结、分析GPT、Gemini、Claude 等文档、资料、总结、方案、问答问题描述要清楚
Agent围绕目标连续执行任务Codex、Claude Code 等代码、项目、流程、自动化任务权限和边界要明确

如何选择工具

可以根据任务需要选择入口：

短问答、初稿和资料讨论可以从 Chat 开始；需要连续处理文件和交付成果时，使用当前可用的 Work 或相关工具。

代码仓库、命令执行和工程修改可以从 Codex 开始；它也可以处理文档与其他连续任务。

  1. 涉及客户资料、报价、合同、源码、硬件设计文件时，必须先判断资料安全边界。
  2. Agent 类工具执行能力更强，因此使用前更需要明确任务范围、资料权限和结果验收方式。

一句话总结：

模型提供理解与生成能力；产品、工具、权限和运行环境共同决定能完成的任务。

1.3 使用前的五条原则

在使用 GPT / Codex 前，应先了解以下 5 条原则。

原则一：AI 只做辅助，不做最终结论

AI 输出的内容可以作为参考，但不能直接作为最终结论使用。

涉及正式文档、客户沟通、项目决策、代码合入、测试结论、硬件判断等内容时，必须由相关负责人或专业人员进行人工复核。

原则二：先判断资料能不能上传

上传前确认资料归属、使用授权和接收服务，重点识别客户身份信息、凭据和未获准传播的项目资料。

按本手册“安全边界”中的方法处理；组织已有授权规则时，以适用规则为准。

不确定时，先不要上传，先询问项目负责人或团队管理员。

原则三：问题描述越清楚，输出结果越可靠

向 GPT / Codex 提问时，应尽量说明：

  • 当前任务是什么；
  • 希望输出什么格式；
  • 背景信息有哪些；
  • 有哪些限制条件；
  • 哪些内容不能编造；
  • 哪些内容需要标注“需人工确认”。

不建议只输入一句很模糊的问题，例如“帮我看看”“优化一下”“写一个方案”。

更推荐使用明确任务描述，例如：“请根据以下测试记录，整理成正式测试报告，要求包含测试目的、测试环境、测试步骤、问题记录和结论，不要编造未提供的数据。”

原则四：敏感资料优先脱敏

客户识别信息和不应传播的内部资料，按任务需要匿名化或删减。已获得授权的工程材料，不仅凭文件类型判断能否使用。

常见脱敏方式包括：

  • 客户名称替换为“客户A / 客户B”；
  • 项目名称替换为“项目A / 项目B”；
  • 人员姓名替换为“负责人A / 工程师B”；
  • 具体金额、利润率、底价等删除或改为区间；
  • 账号、密码、API Key、Token、证书等直接删除；
  • 仓库地址、服务器地址、内部链接删除或替换。

原则五：Codex 修改代码后必须验证

代码生成或修改后，依据项目的验证和合入流程检查实际结果。

使用 Codex 处理代码任务后，必须至少经过以下检查：

  • 人工 Review；
  • 编译检查；
  • 基础功能验证；
  • 必要时进行测试用例验证；
  • 确认没有引入账号、密钥、测试残留代码或无关改动。

1.5 常见登录问题

问题一：无法打开页面或页面加载异常

可能原因包括网络环境异常、浏览器缓存问题、访问方式不符合要求等。

建议处理方式：

  1. 刷新页面或重新打开浏览器；
  2. 尝试使用 Chrome、Edge 等主流浏览器；
  3. 检查当前网络是否符合所在组织允许的访问方式；
  4. 不要自行使用未知代理、插件或第三方工具；
  5. 如仍无法访问，联系团队管理员或 IT 处理。

问题二：账号无法登录

可能原因包括账号密码错误、登录验证失败、账号状态异常等。

建议处理方式：

  1. 确认账号和密码是否正确；
  2. 检查是否需要邮箱、手机号或其他验证方式；
  3. 不要将账号验证码转发给无关人员；
  4. 如多次登录失败，联系账号负责人处理。

问题三：团队成员看不到共享 GPT 或相关功能

可能原因包括账号未加入对应工作空间、权限未开通、入口不正确等。

建议处理方式：

  1. 确认是否使用了团队要求的账号或入口；
  2. 确认是否已加入团队工作空间；
  3. 联系团队管理员确认权限；
  4. 不要自行新建非授权工作区处理公司资料。

问题四：上传文件失败

可能原因包括文件过大、格式不支持、网络异常、权限限制等。

建议处理方式：

  1. 检查文件是否过大；
  2. 尝试转换为 PDF、Word、Excel、TXT 等常见格式；
  3. 确认文件内容是否允许上传；
  4. 涉及敏感内容时，先脱敏再上传；
  5. 如仍无法上传，联系团队管理员处理。

问题五：Codex 无法读取或修改代码

可能原因包括仓库权限不足、未接入项目、分支权限限制、任务描述不清楚等。

建议处理方式：

  1. 确认是否具备代码仓库访问权限；
  2. 确认是否在允许的分支或测试项目中操作；
  3. 提供清晰的任务描述；

确认仓库属于本次授权范围，保护已有修改，并选择适合任务的工作目录与分支。

  1. 修改后必须进行人工 Review 和验证。
